# Checkpoint 1: storyline document format

Write this to `work/storyline.md` (and send it to the user as a file) at Checkpoint 1. It
is the contract for the build: once approved, the deck should be a faithful rendering of
it. Keep it scannable; the user reads it to approve or redirect in a few minutes.

```markdown
# <Client> – <deck purpose> – storyline v1

Audience: <Q1> · Talk: <Q6> min → <N> main slides + appendix · Template: <file>, default content layout "<name>"

## SCQA

- Situation: ...
- Complication: ... (top concerns, customer's words)
- Question: ...
- Answer / governing thought: ... (appears on slide <1|2>)

## Concern / assumption blocks

| # | Concern (customer's words) | RFP ref | Problem statement (impact) | Solution | Proof | Outcome | Priority |
(and/or)
| # | Assumption | Slides that depend on it |

## Pyramid

Governing thought: ...
Ordering logic for key lines: <time | structure | importance | RFP weighting> because ...

1. Key line 1: ... → slides 4-6
2. Key line 2: ... → slides 7-9
3. Key line 3: ... → slides 10-12

## Slide table

| # | Action title | Visual treatment | Template layout | Main / Appendix |

## Your important points (Q7) → where covered

| Point | Slide(s) |

## Self-review

- MECE: <overlaps or gaps found, and what was done>
- Titles-only read-through: <where the story jumps or repeats>
- Weaknesses an evaluator could exploit: ...

## Layout gaps (need your decision)

| Slide | What it needs | Why no layout fits | Options |

## Open items

- [CONFIRM] ...
```
